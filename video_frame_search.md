# Video Scraping & Face Extraction Integration (yt-dlp)

This implementation plan outlines the integration of `yt-dlp` to allow FaceTrace to reverse-search a face against video platforms (like YouTube).

## User Review Required

> [!IMPORTANT]
> Video processing is heavily CPU and memory intensive. On your 8GB RAM machine, downloading a 10-minute video and extracting frames might cause slowdowns. 
> To mitigate this, the plan proposes downloading the video at the lowest possible quality (360p/480p) and only sampling 1 frame per second. Does this limitation sound acceptable to you?

## Proposed Changes

We will introduce a new subsystem that can ingest video links, download them locally, slice them into frames, and feed those frames into the facial recognition matcher.

---

### Dependencies

#### [MODIFY] `requirements.txt`
- Add `yt-dlp` to the project dependencies.

---

### Application Logic

#### [NEW] `app/video.py`
- Create a `VideoTargetProvider` class.
- **Download:** Use `yt-dlp` to download the target URL to a temporary local cache (`data/memory/videos/`). Limit format to `worstvideo` or `[height<=480]` to save bandwidth and memory.
- **Extraction:** Use OpenCV (`cv2.VideoCapture`) to open the downloaded video.
- **Sampling:** Read the video and extract exactly 1 frame per second. Save these frames as JPEG images.
- **Output:** Wrap these frames in `Candidate` objects and return them to the pipeline for face matching.

#### [MODIFY] `app/main.py`
- Update the `--target` URL parsing logic.
- If the target URL contains `youtube.com`, `youtu.be`, `vimeo.com`, or other known video domains, route it to `VideoTargetProvider` instead of the standard `TargetURLProvider`.

#### [MODIFY] `app/search.py`
- Refactor the candidate extraction pipeline slightly if necessary so it smoothly accepts local file paths generated by the video scraper (since standard candidates usually have remote `http` URLs).
